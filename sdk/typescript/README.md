# @docker/docker-agent-ts-sdk

TypeScript types for the docker-agent API (`docker agent serve api`): request
and response bodies, sessions, agent configs and every event streamed by a
session. They are generated from the Go types the server encodes, so they
match the JSON it actually sends.

```ts
import type { AgentStreamingEvent } from '@docker/docker-agent-ts-sdk';

function render(event: AgentStreamingEvent) {
  switch (event.type) {
    case 'agent_choice':
      return event.content;
    case 'tool_call':
      return event.tool_call.function.name;
  }
}
```

The package also describes the builtin tools:

- `<Tool>ArgsSchema`: a strict [Zod](https://zod.dev) 4 schema of the
  tool's arguments, and `<Tool>Args`, its type. `toolArgsSchemas` maps tool
  names to them. Zod is a peer dependency.
- One `as const` list of tool names per toolset (`filesystem`, `shell`, …)
  and `ToolName`, their union.

```ts
import { toolArgsSchemas } from '@docker/docker-agent-ts-sdk';

const args = toolArgsSchemas.read_file.parse(JSON.parse(call.function.arguments));
```

The same types are also available as JSON Schemas (2020-12), one `$defs`
entry per type: `schemas/docker-agent.schema.json` for the API and
`schemas/tool-args.schema.json` for tool arguments.

## Reading the types

- An optional property (`name?: T`) is omitted from the JSON when empty.
- `T | null` means the server may send `null`, usually for an unset list or
  object.
- Timestamps are RFC 3339 strings.
- `AgentStreamingEvent` is a union discriminated by `type`, and so is
  `Toolset`: each variant only has the fields its toolset type accepts.

## Development

Everything under `src/generated/` and `schemas/` is generated by
[`gen`](gen) and committed. Don't edit it by hand; from the repository root:

```sh
task generate-ts # regenerate after changing Go API types or builtin tools
task check-ts    # what CI runs: fails when the output is stale, doesn't type-check or its tests fail
```

`gen/config.go` lists the Go types to expose and how to build each builtin
toolset to read its tools. Types with a custom `MarshalJSON` need a schema in
`gen/overrides.go`: the generator refuses to guess their shape, and fails on
tool argument schemas it cannot translate to Zod.
